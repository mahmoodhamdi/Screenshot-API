# Milestone 1.1: CSRF Protection Implementation

## Status: COMPLETED
## Priority: CRITICAL
## Estimated Effort: Medium

## Context

The Screenshot API currently has **NO CSRF protection**. This exposes the application to Cross-Site Request Forgery attacks where malicious websites could trick authenticated users into performing unwanted actions.

### Risk Level: HIGH
- Attackers could create/delete API keys
- Attackers could change user settings
- Attackers could initiate subscription changes

---

### What Exists
- Helmet middleware is configured in `src/app.ts`

- Auth pages have forms without CSRF tokens
- Dashboard forms submit without CSRF validation

## Requirements

### 1. Install Dependencies
```bash
npm install csurf cookie-parser
npm install -D @types/csurf @types/cookie-parser
```

### 2. Create CSRF Middleware

Create `src/middlewares/csrf.middleware.ts`:

```typescript
import csrf from 'csurf';
import { Request, Response, NextFunction } from 'express';
import { AppError } from './error.middleware';

// CSRF protection using cookies (stateless)
export const csrfProtection = csrf({
  cookie: {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'strict',
    maxAge: 3600 // 1 hour
  }
});

// Middleware to add CSRF token to response locals
export const csrfToken = (req: Request, res: Response, next: NextFunction) => {
  res.locals.csrfToken = req.csrfToken();
  next();
};

// Error handler for CSRF errors
export const csrfErrorHandler = (
  err: Error,
  req: Request,
  res: Response,
  next: NextFunction
) => {
  if (err.code === 'EBADCSRFTOKEN') {
    throw new AppError(
      'Invalid or missing CSRF token',
      403,
      'CSRF_ERROR'
    );
  }
  next(err);
};

// Skip CSRF for API routes (they use API keys/JWT)
export const conditionalCsrf = (req: Request, res: Response, next: NextFunction) => {
  // Skip CSRF for:
  // 1. API routes (they use Authorization header or X-API-Key)
  // 2. Webhook endpoints
  // 3. Health check
  const skipPaths = [
    '/api/',
    '/health',
    '/api/v1/subscriptions/webhook'
  ];

  if (skipPaths.some(path => req.path.startsWith(path))) {
    return next();
  }

  // Apply CSRF protection for browser-based routes
  return csrfProtection(req, res, next);
};
```

### 3. Update app.ts

Add cookie-parser and CSRF middleware:

```typescript
import cookieParser from 'cookie-parser';
import { conditionalCsrf, csrfToken, csrfErrorHandler } from '@middlewares/csrf.middleware';

// After body parser, before routes
app.use(cookieParser());
app.use(conditionalCsrf);
app.use(csrfToken);

// Before error handler
app.use(csrfErrorHandler);
```

### 4. Update Auth Form Templates

Each form needs a hidden CSRF token field. Update the form generation functions:

```typescript
// In form HTML generation
<input type="hidden" name="_csrf" value="${csrfToken}">
```

The `csrfToken` should be passed through the page config from the route handler.

### 5. Update Route Handlers

Auth routes need to pass CSRF token to views:

```typescript
// In auth routes
router.get('/login', (req, res) => {
  const html = generateAuthPage('login', {
    csrfToken: req.csrfToken()
  });
  res.send(html);
});
```

### 6. Update Dashboard Forms

All dashboard forms that submit data need CSRF tokens:
- Settings form (profile update)
- API key creation modal
- Billing forms

## Notes

- CSRF is only needed for cookie-based sessions (browser requests)
- API requests using Authorization header or X-API-Key don't need CSRF
- The Stripe webhook must be exempt (it uses signature verification)
- SameSite=Strict cookie helps but isn't sufficient alone

### Implementation Notes (2025-12-29)

- Used custom Double Submit Cookie pattern instead of deprecated `csurf` package
- Created `src/middlewares/csrf.middleware.ts` with:
  - `csrfToken` - Generates and sets CSRF token cookie
  - `csrfProtection` - Validates CSRF tokens on state-changing requests
  - `conditionalCsrf` - Skips CSRF for API routes (they use JWT/API keys)
  - `csrfErrorHandler` - Handles CSRF errors
- Token uses `crypto.randomBytes(32)` for secure random generation
- Token comparison uses `crypto.timingSafeEqual` to prevent timing attacks
- Cookie settings: httpOnly, secure in production, sameSite strict
- 29 unit tests written covering all scenarios
