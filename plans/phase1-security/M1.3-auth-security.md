# Milestone 1.3: Enhance Auth Security

## Status: NOT_STARTED
## Priority: CRITICAL
## Estimated Effort: Medium

---

## Context

The current authentication system has weak protections against brute force attacks:
- Only 5 requests/minute rate limit on auth endpoints
- No account lockout after failed attempts
- No exponential backoff
- Concurrent limiter is in-memory only (not distributed)

### Risk Level: HIGH
- Brute force attacks on passwords
- API key enumeration attacks
- Distributed attacks bypass per-IP limits

---

## Current State

### Rate Limit Configuration (rateLimit.middleware.ts)

```typescript
// Current: Only 5 req/min per IP
export const authRateLimit = rateLimit({
  windowMs: 60 * 1000,
  max: 5,
  keyGenerator: (req) => req.ip || 'unknown',
  keyPrefix: 'rl:auth:'
});
```

### Issues
1. **No account lockout** - Unlimited attempts possible (slowly)
2. **IP-only tracking** - Easy to bypass with rotating IPs
3. **No tracking of failed attempts** - Can't detect attack patterns
4. **Concurrent limiter uses Map** - Won't work with multiple instances

### 2. Update Auth Service

Integrate lockout checking into login flow:

```typescript
// In auth.service.ts loginUser function
export const loginUser = async (email: string, password: string, ip: string) => {
  const identifier = `${email.toLowerCase()}:${ip}`;

  // Check if locked out
  if (await loginAttemptsService.isLocked(identifier)) {
    const expiry = await loginAttemptsService.getLockoutExpiry(identifier);
    throw new AuthenticationError(
      `Account temporarily locked. Try again after ${expiry?.toISOString()}`,
      'ACCOUNT_LOCKED'
    );
  }

  const user = await User.findOne({ email: email.toLowerCase() });

  if (!user || !(await comparePassword(password, user.password))) {
    await loginAttemptsService.recordFailedAttempt(identifier);
    const remaining = await loginAttemptsService.getRemainingAttempts(identifier);

    throw new AuthenticationError(
      remaining > 0
        ? `Invalid credentials. ${remaining} attempts remaining.`
        : 'Account locked due to too many failed attempts.'
    );
  }

  // Success - clear attempts
  await loginAttemptsService.recordSuccessfulLogin(identifier);

  // ... rest of login logic
};
```

### 3. Move Concurrent Limiter to Redis

Update the concurrent limiter to use Redis instead of in-memory Map:

```typescript
// In rateLimit.middleware.ts

export const concurrentLimit = (maxConcurrent: number) => {
  return async (req: Request, res: Response, next: NextFunction) => {
    const key = getConcurrentKey(req);
    const redisKey = `concurrent:${key}`;

    try {
      const current = await redis.incr(redisKey);

      // Set expiry on first increment (failsafe cleanup)
      if (current === 1) {
        await redis.expire(redisKey, 300); // 5 minute max
      }

      if (current > maxConcurrent) {
        await redis.decr(redisKey);
        throw new RateLimitError(
          `Maximum ${maxConcurrent} concurrent requests allowed`
        );
      }

      // Decrement on response finish
      res.on('finish', async () => {
        await redis.decr(redisKey);
      });

      // Also handle connection close
      req.on('close', async () => {
        if (!res.writableEnded) {
          await redis.decr(redisKey);
        }
      });

      next();
    } catch (error) {
      if (error instanceof RateLimitError) {
        throw error;
      }
      // Redis failure - allow request but log
      logger.error('Concurrent limiter Redis error', { error });
      next();
    }
  };
};
```

### 4. Enhanced Rate Limiting

Add smarter rate limiting that considers failed attempts:

```typescript
// New middleware: adaptiveRateLimit
export const adaptiveAuthRateLimit = async (
  req: Request,
  res: Response,
  next: NextFunction
) => {
  const ip = req.ip || 'unknown';
  const email = req.body?.email?.toLowerCase();

  // Check for suspicious patterns
  const suspiciousKey = `suspicious:${ip}`;
  const isSuspicious = await redis.get(suspiciousKey);

  if (isSuspicious) {
    // Stricter limit for suspicious IPs
    const strictLimit = rateLimit({
      windowMs: 60 * 1000,
      max: 1, // Only 1 request per minute
      keyGenerator: () => ip,
      keyPrefix: 'rl:auth:suspicious:'
    });
    return strictLimit(req, res, next);
  }

  // Normal auth rate limit
  return authRateLimit(req, res, next);
};

// Mark IP as suspicious after multiple account lockouts
export const markSuspiciousIP = async (ip: string) => {
  await redis.setex(`suspicious:${ip}`, 3600, '1'); // 1 hour
};
```

### 5. IP Reputation Tracking

Track IPs that trigger multiple lockouts:

```typescript
// src/services/ipReputation.service.ts

export const ipReputationService = {
  async recordLockout(ip: string): Promise<void> {
    const key = `ip:lockouts:${ip}`;
    const count = await redis.incr(key);
    await redis.expire(key, 86400); // 24 hours

    if (count >= 3) {
      await markSuspiciousIP(ip);
      logger.warn('IP marked as suspicious', { ip, lockoutCount: count });
    }
  },

  async isSuspicious(ip: string): Promise<boolean> {
    return await redis.exists(`suspicious:${ip}`) === 1;
  },

  async clearReputation(ip: string): Promise<void> {
    await redis.del(`suspicious:${ip}`, `ip:lockouts:${ip}`);
  }
};
```
